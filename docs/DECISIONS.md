# GlucoTwin - decision log

Every non-obvious choice made while building this repo, with the reason.

## Phase 0 - environment and scope

1. **The doctor dashboard ships as a web app (React + Convex), not Streamlit.**
   The brief says "build me a web app from this prompt" and the project runs in
   the Freebuff web environment (Vite + React + Convex), where the preview that
   judges will open is the Vite app. Streamlit cannot be previewed here, so the
   clinical UI is React + Plotly-equivalent charts (Recharts) + Convex. The
   Python pipeline stays exactly as specified and feeds the web app.
2. **`app/dashboard.py` (Streamlit) is dropped; `src/api.py` (FastAPI) stays.**
   FastAPI can be exercised end to end in pytest with `TestClient`, so it is
   written and verified. A Streamlit server cannot be verified in this
   environment (no long-running processes allowed), and writing unrunnable code
   breaks the "run everything you write" rule. The spec's `make app` target
   therefore starts the web dashboard instead.
3. **No PyTorch: the two-branch fusion network is implemented in numpy.**
   This machine has ~275 MB free disk, 1 CPU and 2 GB RAM. `pip install torch`
   (CPU wheel) needs several hundred MB, so it cannot be installed here. The
   main model is still a real two-branch fusion network (TCN branch over the
   last 6 hours of 5-channel time series + MLP branch over static EHR, joint
   head for event probability + 3 forecasts), trained with Adam and manual
   backprop, and gradient-checked against finite differences in the test suite.
   `torch` is therefore not in `requirements.txt`.
4. **TCN instead of GRU for the sequence branch.** The spec allows "GRU or
   TCN". On a single CPU core a recurrent loop over 72 steps is far slower than
   a dilated causal convolution that vectorises over time, and the TCN is much
   easier to verify. This keeps `make train` inside a laptop-sized time budget.
5. **Git commits are not possible in this environment.** All git commands are
   blocked ("Git and GitHub commands are blocked; Vly manages version
   control"), so version control is handled by the platform instead of
   per-phase commits.
6. **`docs/presentation.pdf` is generated by a matplotlib renderer, not by
   LibreOffice.** LibreOffice is not installed, so the PPTX (python-pptx, per
   spec) is the source of truth for editing, and a companion PDF with the same
   text on plain white slides is rendered page by page with matplotlib.
7. **Dashboard screenshots.** No browser binary exists in the sandbox and none
   can be installed within the disk budget. `docs/screenshots/` therefore holds
   rendered chart images produced by scripts (real data), and the VIDEO_SCRIPT
   tells the presenter where each screenshot step fits. This limitation is
   stated in the README as well.
8. **Compute and memory budget.** 1 CPU core, ~1.4 GB usable RAM, ~275 MB free
   disk. Consequences, each also documented where the number appears:
   training windows are sampled every 15 minutes (evaluation for the ablation
   table uses the same 15-minute cadence for every model so the comparison is
   fair), the dense 5-minute timeline is used for the deployed model's headline
   metrics, the neural net trains on a fixed random subset of windows per
   epoch, and per-patient artifacts are stored as typed integers in `.npz`.
9. **Scale kept as specified:** 1,500 patients x 14 days x 5-minute resolution
   (4,032 steps per patient, 6.05M rows total) for data generation.
