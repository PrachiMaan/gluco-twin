# GlucoTwin - decision log

Every non-obvious choice made while building this repo, with the reason.

## Phase 0 - environment and scope

1. **The doctor dashboard ships as a web app (React + Convex), not Streamlit.**
   The brief says "build me a web app from this prompt" and the project runs in
   the Freebuff web environment (Vite + React + Convex), where the preview that
   judges will open is the Vite app. Streamlit cannot be previewed here, so the
   clinical UI is React + Plotly-equivalent charts (Recharts) + Convex. The
   Python pipeline stays exactly as specified and feeds the web app.
2. **`app/dashboard.py` (Streamlit) is dropped; `src/api.py` (FastAPI) stays.**
   FastAPI can be exercised end to end in pytest with `TestClient`, so it is
   written and verified. A Streamlit server cannot be verified in this
   environment (no long-running processes allowed), and writing unrunnable code
   breaks the "run everything you write" rule. The spec's `make app` target
   therefore starts the web dashboard instead.
3. **No PyTorch: the two-branch fusion network is implemented in numpy.**
   This machine has ~275 MB free disk, 1 CPU and 2 GB RAM. `pip install torch`
   (CPU wheel) needs several hundred MB, so it cannot be installed here. The
   main model is still a real two-branch fusion network (TCN branch over the
   last 6 hours of 5-channel time series + MLP branch over static EHR, joint
   head for event probability + 3 forecasts), trained with Adam and manual
   backprop, and gradient-checked against finite differences in the test suite.
   `torch` is therefore not in `requirements.txt`.
4. **TCN instead of GRU for the sequence branch.** The spec allows "GRU or
   TCN". On a single CPU core a recurrent loop over 72 steps is far slower than
   a dilated causal convolution that vectorises over time, and the TCN is much
   easier to verify. This keeps `make train` inside a laptop-sized time budget.
5. **Git commits are not possible in this environment.** All git commands are
   blocked ("Git and GitHub commands are blocked; Vly manages version
   control"), so version control is handled by the platform instead of
   per-phase commits.
6. **`docs/presentation.pdf` is generated by a matplotlib renderer, not by
   LibreOffice.** LibreOffice is not installed, so the PPTX (python-pptx, per
   spec) is the source of truth for editing, and a companion PDF with the same
   text on plain white slides is rendered page by page with matplotlib.
7. **Dashboard screenshots.** No browser binary exists in the sandbox and none
   can be installed within the disk budget. `docs/screenshots/` therefore holds
   rendered chart images produced by scripts (real data), and the VIDEO_SCRIPT
   tells the presenter where each screenshot step fits. This limitation is
   stated in the README as well.
8. **Compute and memory budget.** 1 CPU core, ~1.4 GB usable RAM, ~275 MB free
   disk. Consequences, each also documented where the number appears:
   training windows are sampled every 15 minutes (evaluation for the ablation
   table uses the same 15-minute cadence for every model so the comparison is
   fair), the dense 5-minute timeline is used for the deployed model's headline
   metrics, the neural net trains on a fixed random subset of windows per
   epoch, and per-patient artifacts are stored as typed integers in `.npz`.
9. **Scale kept as specified:** 1,500 patients x 14 days x 5-minute resolution
   (4,032 steps per patient, 6.05M rows total) for data generation.

## Publication and secrets

10. **The repository is written to be public, so it holds no credentials.**
    Nothing in the Python pipeline needs a key. The web app reads `VITE_CONVEX_URL`
    from the host environment, and the Convex auth keys (`JWKS`,
    `JWT_PRIVATE_KEY`, `SITE_URL`) stay in the Convex deployment, never in a
    file here. `.gitignore` excludes `.env`, `.env.*` (except the example),
    `.venv/`, `*.pem` and `*.key`, so a local key file cannot be committed by
    accident. A grep for key-shaped strings over the tracked source returns
    nothing.
11. **The demo video and the published link live in the README.** The video
    walkthrough is an unlisted YouTube link and the clinic workspace is a hosted
    preview; both are listed under their own README headings so a reviewer
    reaches them without reading the whole file. The README also carries the
    ICMR-INDIAB citation for the only external statistic it quotes.

## Phase 2 - modelling

10. **Metric cadence is explicit.** The ablation table scores every model at
    the same 30-minute checkpoint cadence so the comparison is fair. The
    deployed model is additionally scored at 15-minute cadence and that denser
    number is the headline, clearly labelled. Without this, the network (which
    is slow on one core) would be compared on a different grid from the trees.
11. **Alarm semantics were rewritten twice before the reported numbers were
    trusted.** An alarm is the first checkpoint of a run above the operating
    threshold, with a 2-hour cooldown. A true alarm must fall in the two hours
    before a real hyperglycemic run start. Alarms raised while the patient is
    already above 180 are not counted as false alarms, because the event has
    already begun and the alert is no longer a prediction. Lead time is reported
    in minutes. The earlier versions counted label onsets instead of glucose run
    starts and produced meaningless 2-minute lead times; those numbers were
    discarded, not patched.
12. **The neural model is not deployed.** It reached test AUROC 0.9496 against
    0.9941 for LightGBM. The brief says to ship the better model and say so;
    both the ablation and MODEL_CARD report the loss.
13. **EHR-only is a static model, so its within-patient AUROC is 0.5 by
    construction.** It is reported anyway, because it is the clearest evidence
    that the CGM stream is doing the temporal work.

## Phase 4 - dashboard

14. **The React clinic workspace reads exported JSON, not a second model.**
    `src/export_web.py` writes `public/data/` from the trained models and the
    twin. The browser never computes a risk or a scenario. This keeps the
    dashboard honest and the Python pipeline the single source of truth.
15. **Clinician actions live in Convex.** Alert acknowledgements and notes are
    per-user state, so they are stored in `alertAcks` and `patientNotes` with a
    user index. Model outputs stay read-only.
16. **The panel is anchored at 20:00, before the evening meal, not midnight.**
    At midnight the evening risk window is already behind the patient and every
    twin looks calm. The
    panel is also stratified (critical / watch / stable) so the cohort screen is
    not 60 identical rows. The panel is a 60-patient slice of the 1,500, chosen
    to show a realistic mix of risk, not the first 60 rows.
17. **Plain-language factors merge duplicate labels.** `hour_sin` and
    `hour_cos` both map to "time of day", so the twin sums their SHAP
    contributions before ranking. Otherwise the why-this-alert panel repeats
    the same sentence twice.

## Phase 5 - documents

18. **`docs/screenshots/` is rendered from exported JSON, not captured in a
    browser.** There is no browser binary in the sandbox. The plates are drawn
    by `src/make_screenshots.py` with the same palette and the same numbers as
    the React app. The README states this rather than implying they are browser
    screenshots.
19. **The presentation PDF is rendered independently of the PPTX.** LibreOffice
    is not available. The PPTX is built with python-pptx as the editable source;
    the PDF is rendered slide by slide with matplotlib using the same text. Both
    are regenerated by `make docs`.
20. **External validation is a script, not a claim.** `src/validate_external.py`
    is complete and smoke-tested on a slice of our own data, but no real external
    dataset was downloaded. The README and MODEL_CARD say it has not been run and
    no external number is claimed.
21. **`data/sample/` is the only committed data.** Three patients, one day,
    written by `src/make_sample.py`. The full 1,500-patient cohort is ignored by
    git and regenerated by `make data`.
